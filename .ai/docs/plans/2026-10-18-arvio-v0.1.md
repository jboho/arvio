# arvio v0.1 design

## Problem

Eval work stalls at the human step. Queues of items wait in JSON or CSV files that a person edits by hand. The files carry no instructions, the context for each item lives in other files, and a typo silently drops a label.

## Goal

One small tool that shows one item at a time, with the question, each choice's meaning and the needed context on screen; keeps the judge's answer hidden until the session ends; and writes labels into the project's own files, where the project's report reads them.

## Decisions

| Decision | Why |
| --- | --- |
| Files are the contract (`task.toml`, `items.jsonl`, `labels.jsonl`); projects never import arvio | Projects differ in language and Python version. A file format works for all of them, and labels stay with the project's data. |
| Standard library only, one command, a local web page | Nothing to install beyond the tool itself; works offline. |
| A `cant_tell` choice in every task, and no skip | Skipping lets the labeler pick the easy items, which biases the sample. "Can't tell" is the honest way out and is counted. |
| Judge hidden until the session ends, then revealed for the whole session | Showing the judge per item anchors the next labels. A reveal row locks the items it names, so a label can't be changed after seeing the judge. |
| Item order from `sha256(seed + id)` | Never the judge's order or the file's order, which can group similar items. |
| Task version = hash of the question, choice keys and meanings, follow-ups and `pin` | Labels made under a different question don't silently mix with new ones. Rewording a title or an example doesn't orphan labels. |
| Append-only label log, fsync'd per row; latest label per item wins until revealed | A crash loses at most the row being written; history stays readable. |
| Kappa only when the judge used 2 or more classes; Wilson range on raw agreement | A one-class judge has no chance agreement to correct; raw agreement with a range is the honest number then. |
| `wilson(0, 0) = (0, 1)` | No data rules nothing out. |
| Server binds 127.0.0.1 on a random port, checks Host, requires a per-launch token, holds a flock per task folder | Item text is untrusted (transcripts, agent output), and two servers writing one log would interleave sessions. |
| Look follows the author's other local tools: panel layout, Space Grotesk and IBM Plex Mono, light and dark | One family of tools, one way of reading them. |

## Split

1. Format, `check`, `add`, `remove`, `status`, stats, atomic file IO, tests.
2. Server, page, `report`, browser check.
3. Release 0.1.0: tag, then install by git URL.

## Out of scope for v0.1

- More than one labeler per task, and inter-labeler agreement.
- A packaged desktop app.
- Active sampling (choosing which items to label next).
